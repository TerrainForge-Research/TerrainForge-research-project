Vertex Data Channels (Data GLB Export)

The "Data Channels" GLB export stores per-vertex terrain data in the COLOR_0 attribute instead of visual biome colors, so engines can read it directly: R = normalized height, G = normalized slope, B = moisture (flow accumulation), A = biome ID / 7. Biome IDs: 0 deep water, 1 shallow water, 2 beach, 3 desert, 4 grassland, 5 forest, 6 rock, 7 snow.

Engineering Roadmap ..î Toward a Deterministic World-Design System

The path from "a procedural terrain generator" to "a deterministic world-design system with shareable generative logic" runs through four phases. Each item below is marked with its status in this build.

Phase 1 ..î Structural Core
1. Deterministic World PipelineImplemented

Generation runs as a fixed, ordered pipeline ..î Seed .Üí Base Height (noise/layers) .Üí Erosion .Üí Rivers .Üí Biome Splat .Üí Mesh ..î entirely driven by the numeric seed and parameter set. The same seed and map code reproduce the exact same world, vertex-for-vertex, on any device.

2. Parameter Graph SystemPartial

The Nodes tab already exposes a visual node graph for building the elevation equation (noise sources, modifiers, combinators). Erosion, biome, and hydrology settings are still flat parameter groups rather than nodes in that same graph ..î unifying them into one graph is the next step.

3. Debug / Visualization LayerImplemented

The Analysis tab renders slope maps, curvature (ridge/valley) maps, flow & drainage, peaks & valleys, and watershed basin segmentation directly from the live heightmap ..î giving visibility into why the terrain looks the way it does.

Phase 2 ..î Differentiation Layer
4. Multi-Pass Terrain SystemImplemented

Base shaping (fBm/ridge/billow/voronoi layers), thermal erosion, hydraulic erosion, river flow accumulation + carving, and biome diffusion via slope/height splat all run as distinct passes over the heightmap.

5. Constraint-Based GenerationPlanned

Not yet implemented. Would add a post-generation solver pass that nudges the heightmap to satisfy spatial rules ..î e.g. "mountains only on the north side", "a river must connect points A and B", "coastal cliffs on the west edge" ..î via iterative correction after the base pipeline runs.

6. QR / Map Code .Üí "World Language"Implemented

The map code now encodes the full deterministic recipe ..î equation, scale/amplitude/octaves, resolution, erosion type and all of its parameters, river generation and carving settings, biome thresholds, colors, density sliders, regions, and layer stack. Loading a code reproduces the world exactly. It does not yet encode a constraint set, since constraint-based generation (item 5) doesn't exist.

Phase 3 ..î Scalability
7. Chunked Terrain + LOD ScalingPartial

Auto LOD (Terrain tab) swaps between full/medium/low-resolution meshes by camera distance, and the export tiers (Low/Medium/High/Ultra) give equivalent control for exported assets. True chunk-based streaming for worlds larger than one heightmap grid is not yet implemented.

8. Versioned Worlds + DiffPlanned

Not yet implemented. Would snapshot the parameter graph after each pipeline stage and provide a diff view ("what changed between version A and B") for iterative world design.

Phase 4 ..î Ecosystem
9. World Forking / RemixPartial

The Seed tab now has a "Fork Variant" button ..î it keeps the entire world recipe (equation, erosion, rivers, biomes, colors, layers) but rolls a fresh seed and copies the new map code, so you get a same-feel variant ready to share. A full lineage/history view of forks is not yet built.

10. Extensible Biomes / RulesPartial

The Biomes tab exposes height-band thresholds (snow line, forest range, beach width) and slope-based rock classification, plus tree/rock density sliders. A full rule system based on independent temperature and moisture fields ..î and community-defined biome packs ..î is not yet implemented.

Roadmap ..î Real-Time Chaos Engine on the GPU

The Chaos Engine's PDE evaluation is currently CPU-bound. Moving the wave field evaluation, gradient computation, erosion, and sediment advection to a WebGPU fragment shader ..î treating the heightmap as a texture and running the PDE as a render pass ..î would enable real-time terrain deformation at 60fps for arbitrarily large grids.

This is essentially the approach used in research-grade fluid simulation on GPUs: each simulation step becomes a full-screen pass that reads the previous height/velocity textures and writes the next state, with erosion and sediment transport implemented as additional passes operating on the same texture set.
